Single source of truth for the "udb-coding" skill; the Claude (`SKILL.md`),
OpenAI (`instructions-udb-coding.md`) and Ollama (`Modelfile.udb-coding`)
packages wrap this content verbatim.

> **Audience:** an AI agent (or human) **contributing code to the UDB
> repository** — implementing plan items, fixing bugs, adding native services or
> backends. NOT for helping app developers *use* a running broker (that is the
> `using-udb` skill). Line numbers drift; locate symbols by name. When this

## 1. What UDB is — the three planes

UDB is a **proto-driven multi-database broker** in Rust (tonic/prost gRPC, sqlx).
Developers declare entities as annotated protobuf messages; from that ONE
contract UDB derives DB schema (DDL), runtime security enforcement, the
descriptor-declared service/RPC surface, six language SDKs, CLI
scaffolds and docs. Three planes:
Current product/SDK baseline is **0.5.10** with wire protocol **1.0.0**.
Version strings must continue to derive from
manifests/`env!("CARGO_PKG_VERSION")`, not hand-coded literals.

1. **Data plane** — the `DataBroker` gRPC service (`Select`/`Upsert`/`Delete`,
   typed cache/document/graph/timeseries RPCs, batch streams, GenericDispatch)
   routed to **18 backends**: postgres, mysql, mssql, sqlite, mongodb,
   cassandra, clickhouse, neo4j, redis, memcached, elasticsearch, qdrant,
   pinecone, weaviate, s3/minio, …(see `src/backend/mod.rs::BackendKind`).
2. **Native control plane** — first-class services (authn, authz, apikey, idp,
   tenant, notification, analytics, storage, asset, webrtc room/peer/track/turn/
   signaling, control-plane, plus the platform wave: vault, metering, scheduler,
   search, webhook, workflow, lock, livequery, config, backup, embedding, cache)
   mounted on a SEPARATE listener (default loopback, broker port+10) — the
   public broker listener serves only health/reflection/DataBroker. A third
   listener (port+20) serves the WebRTC peer plane.
3. **Event plane** — transactional outbox → CDC tailer → Kafka, with journal,
   DLQ, idempotency and tenant-scoped subscriber streams.

**Binary:** `udb` (src/main.rs). **Workspace crates:** `udb` (root),
`crates/udb-portable` (browser/WASM share of parser+IR via `#[path]` includes —
NEVER copies), `crates/udb-wasm` (cdylib bridge for the docs/site playground).

## 2. The proto→runtime pipeline (the spine — understand this first)

```
proto/udb/**  --build.rs(protoc)-->  embedded FileDescriptorSet
   └─ udb.core.common.v1 options: pg_table / db_table_security / column security,
      endpoint_security (auth_mode, scopes, tenant_required, csrf, internal_grpc_only,
      rate policy), native_service (service_id, env key, default_enabled),
      method event contracts `emits[]`  — session.proto is the annotation reference
embedded bytes --> src/runtime/native_catalog.rs   (auto-discovers annotated entity
                   protos; provides embedded_file_descriptor_set())
            --> src/runtime/descriptor_manifest.rs (FdSet::decode → DescriptorContractManifest;
                   descriptor_contract_manifest_static() = OnceLock-cached; decode failure or
                   zero udb services = PANIC — fail-closed, never an empty manifest)
            --> method_security_registry()          (per-RPC security contract)
            --> native_registry.rs                  (service ids, routing, enable flags)
            --> src/generation/**                   (DDL + manifest render)
            --> src/runtime/sdk_manifest.rs         (SDK surface)
            --> docs/generated/udb-native-contract.json + contract-baseline.bin
```
**After ANY proto change** the integrator runs: build →
`udb native contract-baseline --baseline docs/generated/contract-baseline.bin` →
`udb native manifest` (staleness test in `src/cli/tests.rs` diff-gates the
committed JSON) → `buf generate` (raw language stubs) → `udb sdk generate`
(robustness clients, template-driven from `sdk-templates/<lang>/`) → update the
GOLDEN service-set snapshot test deliberately. Never hand-add a Rust id list,
count, or routing table — if you find yourself typing a service/RPC name into a
Rust array, you are probably violating the pipeline (derive it instead).

## 3. Data-plane request lifecycle (file by file)

1. **Listener** built in `src/runtime/service/mod.rs::serve()` — also: startup
   gates (`hardened_startup_violations`, `validate_secure_transport`,
   `validate_compliance_profile` via `UDB_COMPLIANCE_PROFILE`, refuse-to-start
   semantics), singleton-leased startup work (XA recovery), worker spawns
   (saga recovery, CDC tailers, reapers) — all near the saga worker spawn.
2. **Tower layer** `method_security.rs::MethodSecurityLayer::enforce()` — decodes
   the per-RPC contract from the descriptor registry: auth mode
   (public/bearer/admin), scope checks, claim-tenant presence
   (`tenant_required`), public-bootstrap rate limiting
   (`check_public_bootstrap_rate_limit`, key from peer/XFF), loopback/mTLS check
   for `internal_grpc_only`. It installs a task-local **`VerifiedClaimContext`**
   that handlers later bind against. The layer sees HEADERS ONLY — body-carried
   tenant/owner ids MUST be checked in the handler (see §10 flaw 5).
3. **Handler** — `handlers_data.rs` (select/upsert/batch streams),
   `handlers_tx.rs` (transactions, PublishCDC/EnqueueOutboxEvent),
   `handlers_vector.rs`, `handlers_catalog.rs` (migration RPCs),
   `handlers_meta.rs` (GetCapabilities/health), `handlers_admin.rs` (DLQ replay,
   audit verify), `probe_dispatch.rs` (GenericDispatch + the outbox insert).
4. **Fair admission** `channels.rs` — `OperationChannel` enum, per-scope
   (tenant/project/instance) semaphores: `acquire_fair_with_backpressure` /
   `execute_with_channel_scoped(op, ctx, …)`. Batch streams hold the permit per
   item via `native_helpers::execute_stream_batch_item`. All limits/weights are
   resolved ONCE at construction — never `env::var` on this path.
5. **Dispatch** `core/setup_data.rs` — PG read path via
   `planning/broker/mod.rs::build_select_query_plan`; multi-message-type
   selects via `select_join_fusion` + `postgres_helpers::build_join_fusion_sql`
   (tenant predicate from the SHARED resolver, executed in a transaction with
   `set_request_local_settings` (core/mod.rs) so PG RLS session vars apply;
   fails closed when no tenant column resolves). GenericDispatch: an `ir`
   envelope in `spec_json` routes through `ir::compile::<backend>` (tenant
   injection); raw spec runs the executor's generic path with posture honesty
   rules (§7).
6. **Executors** `src/runtime/executors/<backend>.rs` — generic `query/mutate`
   validate raw SQL via `helpers::validate_read_sql/validate_mutation_sql`
   (single statement + verb allowlist); session tenant context via
   `backend_context.rs` (e.g. MSSQL `sp_set_session_context` — no `@read_only`,
   connections are pooled); each executor's `enforce()` reports its RLS posture
   (Enforced/Advisory) and MUST tell the truth per path.
7. **Receipts/fences/consistency** — mutations return a typed
   `MutationResponse.write_receipt` (`WriteReceipt`: source_lsn, outbox_seq,
   projection_task_ids, manifest_checksum) kept in lockstep with the legacy
   `write_receipt_json`; reads may carry `RequestContext.read_fence` and/or
   `consistency_mode` (`ConsistencyMode` enum — wire tokens pinned in
   `src/runtime/consistency.rs::as_str`, honored from both the typed field and
   the `x-udb-consistency` header). Fences use per-backend durability tokens
   (`wait_for_token`) — PG's must gate on `pg_is_in_recovery()` (a PROMOTED
   primary retains a stale non-null replay LSN; that bug shipped).
8. **Durable idempotency** — a keyed replay-safe Upsert/Delete claims a
   tenant/project/message-type/operation-scoped dedup row IN THE SAME
   transaction as the write and persists the first-writer response; a replay
   returns it with `was_duplicate=true` (never re-runs the write); the Redis
   pre-check fails CLOSED when the dedup store is down. SDK retry gating: a
   mutation is auto-retried ONLY when proto `replay_safe` AND a caller key is
   present — keyless replay-safe mutations are deliberately NOT retried (a
   tested contract in all six SDK retry suites; do not "fix" it with auto-keys).

**0.3.7 operator-facing guardrails:** `src/cli/help.rs` answers `udb --help`,
`udb help <cmd>`, command `--help`, and `udb --version` before expensive startup
side effects. `src/cli/args.rs::Command::Requirements` plus the `mod.rs`
handler prints the manifest-derived backend contract and exits non-zero when a
fatal backend is missing. `doctor --enterprise` calls the same project manifest
loading path and reports missing Qdrant/object-store/Redis style requirements
before `serve()` would fail. Keep these paths aligned with runtime prerequisite
logic; do not add a separate, weaker readiness story.

**0.3.7 auth/crypto behavior:** `security_from_request` still requires a JWT
bearer or mTLS on the DataBroker data plane; if only `x-api-key` is present it
returns an explicit `UNAUTHENTICATED` explaining that API keys are not accepted
there. `runtime/encryption.rs::decode_encryption_key` accepts 32-byte base64,
64-character hex/`0x` hex, or raw 32-byte keys, and decode errors name the key
source (`UDB_ENCRYPTION_KEY`, versioned env, or Vault key). Reuse this path.

## 4. Native control-plane lifecycle + service inventory

Handler pattern (every native service follows it — deviations are bugs):
`admit_on(op)` (fair admission) → claim binding (`validate_request_scope` for
body tenant/project; reads bind via `claim_bound_read_tenant`-style helpers,
NEVER trust body ids) → per-action authz where annotated
(`decide_action_native` against the casbin snapshot) → SQL on the native PG
pool → `enqueue_outbox_event` (versioned dot topic `udb.<svc>.<entity>.<verb>.v1`)
→ proto mapping. Pagination via shared `MAX_LIST_ROWS`/`page_response`.

**0.5.0 surface delta (new RPCs + behavior changes — carry these when touching the
data plane or grants):**
- **`DataBroker.BulkCas`** (`handlers_data.rs::bulk_cas_inner` → `setup_data.rs::bulk_cas`) — tenant-scoped, `max_rows`-bounded batch of single-row conditional updates in ONE write tx; each item pins the full PK in `filter`, `changes`+optional `expected_revision`/field-CAS/`increments`; a per-item CAS miss is **counted** (`conflicted`), not a batch error (safe partial retry via `idempotency_key`). Preserves the unary Update path's projection/CDC-outbox/audit side effects. Authorized by the per-call DataBroker `authorize()` (deny-by-default Casbin), NOT a static method_security row; fail-closed on no tenant.
- **Opaque row-revision / ETag** — `SelectRequest.include_revision`, `RecordSet.record_revisions`, `MutationResponse.revision`, `Update/Delete/BulkCas.expected_revision`. Server salted-hash revision map (`system.rs` `udb_row_revisions`, `bump_row_revision_in_tx`, `enforce_expected_revision_in_tx`) — optimistic concurrency for protos with no business `version` column.
- **Soft-delete default live-row scope** — the planner conjoins `<soft_delete_column> IS NULL` into EVERY Select (legacy planner AND neutral-IR bridge, `planning/broker/mod.rs`), and `Delete` on a `soft_delete`-annotated table is now an idempotent `UPDATE … SET tombstone = NOW()`, not a physical DELETE. NOTE: there is **no `include_deleted` wire field** — the "expose tombstoned rows" opt-in did NOT ship; do not document one.
- **RLS update backstop (defense-in-depth)** — the served UPDATE (`build_update_plan`, legacy planner) now appends `AND <tenant> = $N` bound to the VERIFIED caller tenant (mirrors the select/delete IR bridges), so a runtime-level Update naming a foreign tenant matches ZERO rows. Bound in `setup_data.rs::update` via the `parameter_columns.len() == values.len()+1` invariant.
- **Hybrid-tenant reads** — `CompileContext::allow_global_tenant` + `native_entity_read_hybrid_tenant_for_service`. The strict tenant predicate is injected by `SqlDialect::context_predicates` (SQL backends), NOT `util::append_context_predicates` (Cassandra only) — set the flag there to emit `(tenant = $N OR tenant IS NULL)` for hybrid entities like notification global templates.
- **Page-token bound to query shape** — tokens fold a hash of filter+sort+fields; reusing a token under a different query shape ⇒ `FAILED_PRECONDITION` (`pagination.rs`).
- **Lock-fencing at commit** — DataBroker mutations carry optional `lock_name`+`fencing_token`, validated against LockService in the same tx (`enforce_fencing_token_in_tx`).
- **`AuthnService.TransferServiceAccountGrant`** (`auth_service/grants.rs::transfer_service_account_grant`) — atomic service-account identity cutover: re-points an ACTIVE grant's `user_id` under `expected_revision` CAS, both accounts `FOR UPDATE`, dest must be grantless, no cross-project, no window where nobody owns the identity; response returns `previous_user_id` for a deterministic reverse. DESTRUCTIVE, scope `udb:authn:manage-grants`.
- **`udb deploy`** (D-1..D-4) — declarative `udb.deploy.yaml` + `udb deploy plan|apply|render {env,compose,helm,kube}`; from minimum args derives the full production env (UDB_ENV, 3 mTLS flags, JWT/JWKS, listeners, RLS, audit) and idempotently reconciles project/auth-bootstrap/grants/api-keys/policies + `udb secrets init`. Plus `udb doctor --json` compat manifest (descriptor hash / versions / capabilities) and a BrokenPipe-safe `cli::emit()` sink.

## 5. Event plane / CDC (`src/runtime/cdc/`)

- **Outbox→Kafka tailer** `engine_tail.rs::run_tailer`: poll rows
  `delivery_state='pending'` → mark `publishing` (state-tracked modes) →
  produce → journal (`udb_cdc_event_journal`, full payload; retention sweep
  `run_journal_retention_sweep` keyed to `idempotency_ttl_secs`) → ack
  (`ack_event` DELETEs the outbox row in exactly-once modes — replay therefore
  reads the JOURNAL, not the outbox).
- **Delivery modes:** AtLeastOnce / StateMachine / KafkaTransactional. In-doubt
  recovery (`indoubt_recovery.rs::reset_indoubt_publishing_rows`) runs at
  startup AND periodically from the maintenance tick for ALL state-tracked
  modes; delivery-timeout arms reset the in-flight row (pending, or acked when
  a recorded kafka offset proves commit). `producer_epoch` fences duplicates.
- **Generic sources** (PG-table/MySQL/Mongo, wired in `service/mod.rs`):
  `tail_source` — per-event decision is `tail_source_publish_decision`
  (Err ⇒ Abort BEFORE journal/offset persistence; the supervisor restarts from
  the last offset → at-least-once). Deterministic ids via
  `source_cdc_event_id` (also for DLQ rows — ON CONFLICT dedup).
- **DLQ** `engine_dlq.rs::route_to_dlq` — durable DLQ insert FIRST, then mark
  `dlq`; insert failure resets to `pending`. Replay RPC unwraps the envelope
  (`catalog_admin::replay_dlq_event`).
- **Subscriber streams** `stream_cdc`: tenant filter is FAIL-CLOSED for every
  topic (an event carrying a foreign tenant_id never reaches a differently-
  scoped subscriber; `topic_policies` consulted at subscribe);
  `since_event_id` replay from the journal with created_at fallback.

## 6. Durable system state & transactions

- **Canonical store** (`src/runtime/canonical_store/`, 9 backends): one trait
  for advisory leases (single-winner; Redis lease ops are Lua-atomic; Neo4j
  lease nodes are pre-seeded tombstones), monotonic outbox sequence allocation,
  saga/admin-audit/migration-audit records, projection task queue, durability
  tokens + `wait_for_token` fences. Shared logic lives in `system_store.rs`
  (`JsonSystemRecordAdapter` / `JsonProjectionTaskAdapter`) — vector/KV stores
  delegate to it. Registration in `setup_data.rs::register_full_canonical_store`
  refuses Projection-role backends (vector stores, ClickHouse) unless
  `UDB_ALLOW_PROJECTION_SYSTEM_STORE=1`. Live conformance:
  `conformance_live_tests.rs` (env-gated per-backend DSNs, runs in CI).
- **2PC/XA** (`src/runtime/xa.rs`, `xa_recovery.rs`, `core/tx_object.rs`):
  `XaCoordinator::execute_with_write_ahead` writes the commit-intent ledger row
  AFTER prepares, BEFORE the first `COMMIT PREPARED` (write-ahead decision).
  Recovery: `recover_xa_ledger_indoubt` (paginated, `INDOUBT_SCAN_PAGE_SIZE`)
  drives ledger intents; the presumed-abort sweep
  (`recover_abandoned_prepared_transactions` → `prepared_sweep_action`) only
  aborts xids with NO ledger row — committed/commit-intent rows are
  committed/skipped, never rolled back. Gated by `UDB_2PC_ENABLED`.
- **Sagas** (`saga.rs`): compensation records in the canonical store; a
  leader-elected recovery worker re-drives; vector compensations capture the
  exact backend instance.

## 7. IR, parser, generation, migration

- **Parser** (`src/parser/`): annotation option tables in `options.rs`
  (`option_kind` matches bare or `udb.`-prefixed names; custom namespaces via
  `UDB_PROTO_NAMESPACE`); numeric values parse fallibly with
  `ParserDiagnostic`s (Warn/Strict); facade types in `facade.rs` (shared with
  udb-portable via `#[path]`). The CLI compat-matrix derives from these tables.
  The 0.3.7 CLI also performs a raw-source lint hint for dense one-line field
  annotations packing multiple aggregate options on one physical line; this is
  a non-fatal editor/language-server formatting warning, not a descriptor rule.
- **IR compilers** (`src/ir/compile/`): `Compiler` per backend ×18;
  `compile_for_backend` is THE feature matrix (plugin conformance reads it —
  one source). Tenant/project predicate injection (`util::resolve_tenant_column`
  — the ONE shared resolver honoring `is_tenant_column`, `tenant_id`,

  envelope in GenericDispatch `spec_json`. 152 cross-backend tests in
  `ir/cross_backend_tests.rs`. Semantic divergence on a backend = compile
  error/`Unsupported`, never silent reinterpretation.
- **Generation** (`src/generation/`): `generate_bootstrap_sql`, artifact render

  EXCLUDED from unattended bootstrap.
- **Migration** (`src/migration/`, `src/control/`, `core/catalog_admin.rs`):
  diff model `ChangeKind`/`ChangeOperation`/`ChangeSafety` + `diff_manifests`;
  startup FSM `control/lifecycle.rs::run_startup_lifecycle_core` (review gate
  `reject_review_required_sql_artifacts` runs BEFORE any apply, both branches);
  sealed approval plans (`plan_approval.rs::ApprovedPlan`, HMAC + quorum —
  REQUIRED when `UDB_APPROVAL_SIGNING_KEY`/quorum configured); RPC path

## 9. The ten directives (each exists because an audit caught its violation)

1. **Proto is the source of truth** — §2 pipeline + regen protocol; no Rust id
   lists.
2. **Reuse before you write** — grep `native_helpers.rs`, `singleton.rs`,
   `ir/compile/util.rs`, `system_store.rs` first. Four divergent tenant
   resolvers once shipped; the weakest one caused a cross-tenant leak.
3. **No code islands** — wire-in over delete. Verify reachability:
   `grep -rn "<fn>" src/ crates/ tests/ build.rs` — registry/macro wiring
   counts; `#[cfg(test)]`-only callers do NOT.
4. **No capability lies** — `enforce()` postures, capability matrix, health,
   conformance, docs must match the serving path; downgrade the claim in the
   same commit if you can't make it true.
5. **No hardcodes** — named const or env resolved ONCE (OnceLock/constructor).
   Version strings via `env!("CARGO_PKG_VERSION")`. The channels hot path once
   did 15–20 `env::var` calls per request — never again.
6. **No stubs** — real impl, or typed `failed_precondition` + honest
   mounted-but-degraded health. Never `todo!()`, never fake success, never
   `unimplemented` (clients retry it differently).
7. **Fail closed** — audit-confirmed fail-opens to never repeat: empty tenant
   filter returning ALL tenants; non-`udb.` CDC topics skipping the tenant
   filter; unreadable policy file ⇒ lint passes; unsigned plan accepted with a
   signing key configured; unresolvable tenant column ⇒ isolation skipped.
   READS need claim binding too (GetUser/ListUsers once leaked cross-tenant).
8. **No in-memory stores, ever** (tests included) — canonical store/PG +
   env-gated live tests (§8).
9. **Tests call the served path** — the audit's #1 finding was "real fix,
   mirror test". Would reverting the fix fail your test? If unsure, revert
   locally and check. Extract a pure decision fn ONLY if the serving code then
   calls it.
10. **Cargo discipline** — batch edits; one `cargo check` per wave; one
    `cargo test --workspace --lib` at the end (§8 notes).

## 10. Flaw catalog — interrogate your own diff before claiming DONE

1. **Island?** Serving-path caller exists (grep)?
2. **Duplicate?** Does `native_helpers`/`util`/`system_store` already provide it?
3. **Hardcode?** Policy-like or repeated literal? Env read per request?
4. **Stub?** Any success without the work?
5. **Fail-open?** Guard skips when unresolved? Read RPC trusting body
   tenant/owner? Method-security sees headers only — did the handler bind the
   body to the claim?
6. **Capability lie?** Posture/matrix/health/doc now overstates the code?
7. **Mirror test?** Real function called? Reverting the fix fails it?
8. **Unbounded?** New map/label/buffer growing with requests/tenants?
   (clear-all is not eviction; request-derived metric labels go through
   `metrics.rs::bounded_label`.)
9. **Hot-path waste?** Per-request env/fs/descriptor-decode/clone? (use
   `descriptor_contract_manifest_static`, OnceLock.)
10. **Fence?** Touched outside assigned scope, or a generated file
    (`docs/generated/**`, `sdk/*/gen/**`, generated clients)? Report instead.

## 11. New native service recipe (ship all five or it's a regression)

1. Protos `proto/udb/core/<svc>/v1/` (+`services/v1/`) fully annotated (copy
   session.proto entity style + tenant service endpoint style); events
   `udb.<svc>.<entity>.<verb>.v1` with partition key + delivery guarantee.
2. Impl `src/runtime/service/<svc>_service/mod.rs` following §4's handler
   pattern exactly; durable state in PG; workers leader-elected.
3. Mount in `service/mod.rs`'s native-listener block (copy an adjacent
   `add_service` line); enable flag derives from the descriptor.
4. Regen protocol (§2) + GOLDEN snapshot updated deliberately.
5. Ship WITH: casbin policy seeds, runbook section (docs/auth-runbooks.md
   style), capability-matrix entry, env-gated live test, and entries in the
   `declared_emits_reconcile…` map for every topic.

## 12. Definition of done

Every DONE-when bullet true · reachability verified by grep · tests call the
served path (live env-gated where DB-inseparable) · no new warnings · evidence
note `— DONE (date): <what> (file:line)` · out-of-fence edits reported, not
made. An honest `[~]` beats a false `[x]`: completion claims are re-audited
adversarially against source, and false completions ARE found.

## 13. Releasing a version (the full checklist — do IN ORDER)

Version is one source of truth: `versions.json`. **Never hand-edit a version
anywhere else.**

1. **Bump.** Edit `versions.json`, then `node scripts/check-versions.mjs --fix`.
   This propagates to `Cargo.toml`, `Cargo.lock`, every SDK manifest/launcher/
   generated client, `docs/generated/udb-native-contract.json`, swagger, the
   release-workflow refs, AND `docs/site/**` (footers, index pill, sdks install
   table — these are now gated; they previously drifted to 0.3.6 unnoticed).
   Verify with `node scripts/check-versions.mjs` (exit 0 = the CI gate).
2. **Proto/RPC change?** Run the full ch17 9-surface regen FIRST (buf stubs →
   `udb native manifest/docs` → GOLDEN → bench bodies+counts → authn/authz
   inventory → http-api report). A pure version bump needs NO regen.
3. **Local gate sweep BEFORE any push** (hard-won: docs changes break gates that
   pin *exact prose strings*). Run at minimum:
   `node scripts/check-versions.mjs` · `check-beta-versioning-posture.py`
   (pins beta-compat sentences in VERSIONING.md + api-rules.md) ·
   `check-doc-service-counts.py` (NO hand-written `N services/M RPCs` in prose —
   counts live only in the README generated block) ·
   `check-docs-ci-freshness-posture.py` (pins strings in native-services.md) ·
   `check-markdown-links.mjs` · `check-error-detail-posture.py` ·
   `check-openapi-operationid-posture.py` · `check-bench-harness-posture.py` ·
   `cargo fmt --check` (edition 2024). Fixing a doc AFTER it fails CI wastes a
   full runner cycle — sweep locally first.
4. **PR → main.** PR CI runs the FAST subset (`if: github.event_name ==
   'pull_request'`). Green here ≠ fully validated.
5. **Merge → main.** Main CI (`push` event) runs the FULL matrix: the
   push-gated jobs (SIMD, AArch64, live canonical stores, Plugin-feature ×
   backends, Auth-binary × platforms) that PRs skip by design.
6. **WAIT for main CI green BEFORE tagging.** `release.yml`'s `ci-green` gate
   requires main's full CI green; tag too early and the release fails at the gate
   with everything downstream skipped (not failed — skipped). If it does, fix
   main CI then `gh run rerun <release-run-id>`.
7. **Tag `v{version}`.** `git tag v{version} origin/main && git push origin
   v{version}` → `release.yml`: ci-green → build-binaries × 5 platforms (release
   profile, slow — 20–40 min) → publish crates/docker(ghcr)/npm/pypi/nuget/
   packagist → GitHub Release + assets. Publish only starts after ALL binaries.
8. **Benchmarks + Pages.** `benchmark-sdks.yml` triggers on `Release` completion
   (`workflow_run`); `pages.yml` is the SOLE Pages deployer (consumes the
   `sdk-benchmark-results` artifact). GOTCHA: the release-gated bench job runs
   only when the triggering run's `head_branch` starts with `v` — it often
   `skipped`s, leaving stale live benchmarks. Fallback: `gh workflow run
   benchmark-sdks.yml -f release_tag=v{version} -f
   release_asset=udb-linux-amd64-full`.
9. **Verify live.** `gh release view v{version}` (all 5 assets + publish jobs
   success); the published crate/npm/pypi/nuget; and the GitHub Pages site shows
   the new version + fresh benchmarks (not a stale RPC count).

**Env gotchas:** the local full-crate build is flaky (disk fills
`target/debug/incremental` → `rm -rf` it + `CARGO_INCREMENTAL=0`; linker
`LNK1104` temp locks). For a local SDK grind, prefer downloading the release
binary (`gh release download v{version} -p udb-windows-amd64.exe`) over building.
