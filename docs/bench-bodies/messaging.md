## MessagingService
_proto: core/messaging/services/v1/messaging_service.proto_

Bytes fields are base64 in these JSON bodies.

Every row runs its success path. The MLS objects (device credentials and signature keys, KeyPackages, GroupInfo, ratchet trees, a commit with its Welcome, a PrivateMessage) are minted for the benchmark tenant and subject by `udb messaging bench-fixture`, the `udb-mls` client crate the SDKs use. `scripts/prepare-benchmark-fixtures.py` runs it after each database reset, sends its `setup` requests (register the measured, peer and revoke devices; publish the peer's KeyPackages and the measured device's last-resort package; create the message group and the commit group; add the peer to the message group, which moves it to epoch 1 and gives the measured device an inbox entry; store the `sdk-perf-backup` and `sdk-perf-backup-delete` backups), and hands the rows their `<seed:mls_*>` values. Each mutation row has a target of its own, so the rows succeed in any order and each consumes its target once:

- `RegisterMessagingDevice` registers a fourth device nobody registered; `PublishKeyPackages` publishes a fresh one-time package of the measured device; `ClaimKeyPackages` claims one of the peer's packages (its last-resort package backs any further claim); `CreateGroup` creates a third group; `SubmitCommit` adds the peer to the commit group at epoch 0 (Welcome included); `SendMessage` sends a PrivateMessage sealed for the message group's epoch 1; `RevokeMessagingDevice` revokes a disposable device that is in no group.
- Reads (`ListMessagingDevices`, `GetKeyPackageStock`, `GetGroupInfo`, `StreamInbox`, `GetMessagingBackup`) and `AckInbox` use the measured device and the message group. `PutMessagingBackup` and `DeleteMessagingBackup` need no MLS object: the broker checks only the backup envelope framing (`UDBMLSB1` magic and the minimum length).

Against a broker older than 0.6.0 (no MessagingService) the seed skips the messaging setup and these rows fail with `UNIMPLEMENTED`.
